# Lessons from prior work
Examples only; the main skill owns workflow and approval rules.

- TransplantID's numbered pastel phases, strong headings, useful illustrations and explicit arrows communicated better than generic card redesigns. Preserve informative density.
- Content can be wrong despite successful rendering tests: an academic-records figure needed the actual weekly action list and first-use behavior, not merely an approval diagram.
- Repeated record categories and CV/website illustrations made Initialization and Maintaining visibly connect.
- Patch after patch to awkward arrows exposed a composition problem. Arrange stages and connectors before styling; compare alternative layouts without losing agreed facts.
- Mixed shaded raster action icons and simple line art weakened cohesion. Authentic service logos can differ; other illustrations should form a family.
- A prior website drawn as an empty rectangle looked unfinished beside a populated output browser.
- Floating expansions can be difficult on phones. A text accordion is not an equivalent visual replacement unless agreed.
- Windows-local SVG/PNG links failed on the user's phone; a static SVG in the supported conversation viewer worked.
- TransplantID's historical model development, weekly discovery, inclusion decisions and publication are distinct phases. Ranking is not study-quality assessment; Zotero inclusion can bypass review; planned API publication must remain labelled planned. These are examples of accurate semantics, not transplant facts to copy into other topics.
